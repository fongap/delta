## Human-Control Verification

R5.1 live steering uses the pre-existing runtime authority rather than a second control registry:

`busy WebSocket user_message → RuntimePort.steer → TurnEngine.queue_steering → next safe iteration boundary`.

The desktop main Composer remains available while a turn is active. The regression in
`tests/test_server.py::test_ws_routes_second_plain_text_to_active_turn_without_concurrency`
verifies that the second plain-text message is not rejected, does not create concurrent provider
execution, and is injected into the same turn. Existing runtime-port and engine steering tests
continue to cover the lower-level queue/injection contract.

The regression intentionally does not require an exact provider call count. Steering must cause at
least one subsequent model iteration, while unrelated work such as automatic title generation may
legitimately add provider calls. The invariant is single active execution plus successful steer
injection, not a fixed number of model invocations.

Follow-up is intentionally not exposed in R5.1 because no distinct durable follow-up queue contract
is implemented end-to-end. Cancel continues to use the existing interrupt path.
